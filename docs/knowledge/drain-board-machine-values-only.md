# drain報告板は機械値だけで作る（2026-08-12判断）

## 選択

monocoreの `/drain`（drain報告板）に出す「何をして／どうなったか」の組は、**ラッパー（`drain.ps1`）が持つ機械値と `traces/<task-id>.json` の `steps[]` だけ**で組み立てる。**drainセッションに構造化ブロック（`----- RUN_JSON -----` 等）を出させる案は採らなかった**（AIが2案を提示し、本人が機械値だけを選択）。

## 理由

- **無人経路に自己申告を増やさない**。taskboxは「完了は自己申告で決めない、機械判定を根拠にする」（完了ゲート）で一貫しており、報告板もその側に置く。SKILL.mdの変更が要らないので手順も増えない。
- **非対称性**: queueが空で保守工程だけの回はカードが薄くなる（「板更新=済」「バックアップ=成功」程度）。**薄すぎたら後からセッション側に出させて厚くできるが、逆に一度増やした自己申告を減らすのは面倒**。まず薄い側から始める。

## 前提として確認した事実

- **`traces/*.json` の `steps[]` は既に `{desc=何をして, note=どうなったか}` の組**であり、新たに書かせるものは何も無かった。
- **`drain.log` はファイルとして読み返す必要が無い**。同じ内容は `drain.ps1` が `$out` としてメモリに持っており、ログ側は7日ローテーションと並行書き込みがある。**情報源はdrain.logか、という当初の見立ては中身としては正しく、取り方だけが違った。**
