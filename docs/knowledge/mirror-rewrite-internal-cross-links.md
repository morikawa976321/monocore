# ミラーする文書間の相対リンクは同期時に書き換える（2026-08-09）

[[monocore-mirror-design-principles]] の2原則（集合の一致・単一形式保持）に続き、`/reports`実装（`mf/reports/*.md` → monocore）で新たに踏んだ論点。

## 問題

ミラー元のコンテンツ同士が相対リンクで参照し合っている場合（例: `design_language_unification_briefing.md` から `[本文](product_sales_roadmap.md)`）、そのまま変換すると`<a href="product_sales_roadmap.md">`になり、ミラー先のURL構造（`/reports/product_sales_roadmap`、拡張子なし）と食い違って404になる。スマホでレポートを読みながら関連レポートへ飛ぶ、というまさにこの機能が想定する使い方で踏む。

## 対処方針

同期スクリプト側で、変換パイプラインの中にリンク書き換えのステップを挟む:

- 対象は「相対パスかつ`.md`で終わるリンク」のみ（外部URL・絶対パス・アンカーのみは対象外）。
- 書き換え先のslugが**同期対象に実在する場合のみ**書き換える（`/reports/<slug>`）。archiveへ移動済み・削除済みなど同期対象外を指すリンクは、書き換えても別の404になるだけなので元のまま残す。
- 判定に使う「同期対象slugの集合」は、その回の同期でローカルから読み取ったファイル一覧から作る（DB問い合わせ不要）。

## 一般則

**ローカルの複数ファイルを1つのミラー先(URL構造の異なる別システム)へ同期するとき、ファイル間の相互参照(相対リンク)は変換漏れに気づきにくい。** 該当ファイルが少数でも(今回は32本中1本)、実際に踏む導線を塞がないためには「壊れたリンクを放置しない」対処を同期パイプラインに組み込む方が、個別の記事を手で直すより保守コストが低い。
