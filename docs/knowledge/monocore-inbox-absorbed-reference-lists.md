# 人間向け参照リストがinboxブロブに流入している（2026-07-21確認）

## 事実

- monocoreの `inboxes.content`（1ユーザー1行のTEXT）の実内容を確認したところ、**266行・10,672字**の中に、実行タスク・やりたいことリスト・研究の種・内面/創作メモ・**人間が常時読む参照リスト（読みたい本70冊超・筋トレメニュー・発声トレーニング・会話術）**・認証情報が未分化に同居していた（認証情報については [[monocore-inbox-holds-plaintext-credentials]]）。
- このうち参照リストは、[[monocore-user-gateway-decision]] の棚卸しで **knowledgeの実コンテンツ**として名指しされていたもの。knowledgeは2026-07-18に全7行が空の状態で削除された（[[monocore-list-pages-reconsideration]]）。**面が消えた後、中身は消滅したのではなくinboxブロブへ移動していた**。

## 示唆

- knowledgeが空になった原因は「使われなかった」ではなく、**レコード型CRUD（title/body/status/並び順）の入力コストが、単一テキストエリアへの追記に負けた**可能性が高い。ユーザー申告の問題点「入力が面倒でサボる」（[[monocore-user-gateway-decision]]）と整合する。
- **決定間の緊張（2026-08-06更新: 凍結解除により解消可能になった）**: 発見当時は「人間向けの面はmonocoreに一本化」（2026-07-14の [[monocore-user-gateway-decision]]）と「monocoreは全面凍結」（2026-07-21〜2026-08-06）が同時に有効で、**人間が常時読む静的リストの正しい置き場が制度上どこにも無かった**。当時のinbox同居は規律の失敗ではなくこの2決定の論理的帰結。**凍結は2026-08-06に解除された**（[[monocore-third-pillar-of-ai-platform]]）ため、これは「実装で解ける未決問題」に変わった — 参照リストの面を作るか、既製ツールへ出すかは未決のまま。
- **なぜ起きたか**: 責務境界を「情報の寿命軸」「読者軸（AI向け/人間向け）」で切っていたが、この領域では「**実装余力があるか**」という第3の制約が効いており、寿命・読者だけでは行き先が決まらない。

## How to apply

inboxの整理を設計するときは、**参照リストの行き先を先に決める**（凍結を部分解除して面を作るか、この種の純参照リストだけAI活用基盤の外の既製ツールへ出すか）。決めずに仕分けを始めると、参照リストだけが必ずinboxに残る。
