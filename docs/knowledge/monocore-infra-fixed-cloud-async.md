# 決定: monocore v2インフラは束A(Supabase維持)+非同期AI対話構造(2026-07-14)

- **選択1**: monocore v2のインフラは**束A=Supabase現状維持**で確定。SQLite移行案は取り下げ。常時稼働ノード導入もなし。
- **選択2**: **人間と(ラップトップ上の)AIが非同期にやりとりする構造**を採用。スマホからのメッセージはSupabaseに溜まり、ラップトップ起床時にブリッジが処理・返信する。AIはローカルLLM・クラウドLLMのいずれも想定(multi-ai-delegationスキルの枠組みと整合)。
- **理由**: 動機はデータ主権ではなく運用のシンプルさ(2026-07-14ユーザー明言)。マネージドサービス維持が「何もしない」運用で最も認知負荷が低く、非同期化により「電車移動中にスマホから使いたい vs ラップトップは鞄内でスリープ」という制約衝突が実用上塞がるため。リアルタイム性が必要な場面(自宅・研究室)ではラップトップは稼働している。
- **経緯**: [[monocore-user-gateway-decision]]を受けた基盤選び。シンプル化動機の下で選択肢は「(a) Supabase現状維持 (b) 完全ローカルアプリ化(モバイル利用の放棄を含む)」の2択に収斂していたが、非同期構造の採用で(a)がモバイル要件も満たすことになり確定した。
- **帰結**: モバイル利用(特にスケジュール面)は維持。3自由度要件([[front-ui-requirements]])のうち場所・デバイスは束Aで達成、入力方法(音声)はPhase 3で実装。
- **UX確認(2026-07-16)**: 外出中はチャットの返信が「ラップトップを次に開くまで来ない」体感になる仕様を、ユーザーが許容確認済み。/agentページ(エージェントセンター)の表示粒度(board写像が要約で足りるかタスク全文まで見たいか)はM5到達時に改めて判断。
- 設計の正はmonocoreリポジトリの `docs/design.md`（2026-08-06更新。旧 `docs/monocore-v2-design-draft.md` は同日に廃止・分割 — [[monocore-phase-plan-abandoned]]）。「今後の大枠議論はPhase 3実装後に行う」という計画（2026-07-17）はフェーズ計画の廃止により失効した。本ノートのインフラ決定（束A・非同期構造）自体は現在も有効。
