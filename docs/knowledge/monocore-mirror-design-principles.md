# monocoreミラーの設計2原則（2026-08-09）

[[reports-mobile-access-via-monocore]] の設計中に本人が示した方針。reports以外のミラーにもそのまま効く。

## 1. 同期は「集合の一致」であって upsert ではない

ローカルをスキャンして upsert し、**DBにあってローカルに無い slug は delete する**。upsertだけだと消したもの・archiveへ移したもの・リネームしたものがミラーに残り続け、ローカルが正という原則が破れる。archive移動・削除・リネームを個別に扱わず、1つの仕組みで処理できるのも利点。

## 2. 導出物は単一形式でのみ持つ

同じ内容をmdとHTMLの両方で持つような二重保持をしない。片方を捨てて失う機能（例: 本文の全文検索）は、**カラムを足すのではなく別の手段で代替する**（例: 検索対象をタイトルと見出しに絞り、本文内はブラウザのページ内検索に任せる）。

## 付随して確認した事実

容量は当面この設計の律速にならない。reportsの実績は約1MB/月、context-engine 02_context全体でも377ノート1.18MBで、Supabase無料枠500MBに対して桁が違う。加えてPostgresのTOASTが2KB超のtext列を自動圧縮する。**上の2原則は容量対策ではなく、正しさのために採る。**
