# PIMアプリ 全ページ共通レイアウト仕様

## 1. 設計指針
本アプリは、PIM（個人情報管理）における**「操作速度の最大化（手数の削減）」**と**「認知負荷の最小化（情報の整理）」**の高度な両立を設計の根幹とする。

## 2. コアUIコンポーネント定義

### 2.1 ナビゲーション・サイドバー (Navigation Sidebar)
* **配置**: 画面左端の極狭い領域。
* **挙動**: 普段は不可視、あるいは極めて薄い（Opacity 5~10%）境界線のみを表示。マウスホバーによってナビゲーションメニューが展開される。
* **役割**: 画面切り替え（Inbox, Knowledge等）の制御。
* **採用理由**: 非操作時の視覚的ノイズを「ゼロ」に近づけ、メインコンテンツへの没入感を最大化するため。
* **スピード対策**: 小さなボタンを探してクリックする手間を省き、画面端への「大まかなマウス移動」のみで即座にメニューへアクセスさせる。

### 2.2 センター・フォーカス・モーダル (Center Focus Modal)
* **配置**: 画面中央。
* **挙動**: リストアイテムの選択時に発火。背景に強力なブラー（ぼかし）を施し、背後の情報を完全に遮断する。
* **役割**: 詳細情報の閲覧および編集。
* **採用理由**: 
    * **人間工学**: 閲覧・編集という高負荷な作業において、視点を中央に固定することで、身体的・精神的な疲労を軽減する。
    * **深い集中**: 背景を遮断することで「今は編集モードである」という脳の切り替えを促し、シングルタスクへの没入を支援する。
* **操作性**: `Esc` キーまたはモーダル外の暗がりをクリックすることで迅速に離脱可能。

## 3. UIパターンの比較検討と採用根拠

### 3.1 ナビゲーション手法の比較
| パターン | 採用 | 不採用理由・備考 |
| :--- | :---: | :--- |
| **サイドバー (常駐)** | × | 常に視界に情報が入り、認知負荷を高めるため。 |
| **ナビゲーション・レール** | × | アイコンが常に露出しており、ノイズ最小化の観点で次点。 |
| **ハンバーガーメニュー** | × | アクセスに「ボタンを探す」「クリックする」という2ステップを要するため。 |
| **サイドバー（ホバーで表示）** | **○** | **ノイズゼロとクリック最小化を両立。** |

### 3.2 詳細情報の提示手法の比較
| パターン | 採用 | 不採用理由・備考 |
| :--- | :---: | :--- |
| **サイドシート (右側)** | × | 視線が右に偏り、人間工学的に長時間の編集に向かない。また、一覧が常に視界に入るためノイズとなる。 |
| **フルページ遷移** | × | ページロードの待機時間と、元の文脈（一覧）の完全な喪失を避けるため。 |
| **センターモーダル** | **○** | **視界のノイズを排し、中央での集中した閲覧・編集を実現。** |

## 4. 適用画面構成
本アプリでは、上記のレイアウトを標準仕様として原則適用する。ただし、画面固有の要件や複雑性により標準仕様では操作性・視認性が損なわれる場合に限り、例外として最適なUIパターンの採用を検討する。

1.  **Inbox**: 一時保管・クイックメモ（プレーンテキスト）
2.  **Task & Schedule**: タスク管理および時間軸での予定管理
3.  **Knowledge**: ナレッジ・メモ蓄積（Markdown）
4.  **Item**: 所持品・ウィッシュリスト管理
5.  **Finance**: 収支・資産管理

## 5. 将来の拡張性
画面数が増加した際も、センサーエッジ内のリスト更新のみで対応。基本レイアウト（AppShell）の構造を変更することなく、ミニマルな保守性を維持する。
