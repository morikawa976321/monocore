# monocoreの仕様決定の過程で出たアイデア

monocoreの設計に関する調査結果や検討事項を列挙したメモ

## 既存の類似サービスの分析

- Obsidian：メモに関係性の情報を持たせられる。ひとつのメモを複数の文脈に同時に存在できる。リンクによって関連メモを迅速に探せる。あとからネットワーク全体を見返したときに意外な結合の法則性に気が付く（複数の異なる領域が同じキーワードでつながっていた、など）
- Logseq：日ごとに1つのファイル。そこにすべてをタグとともに書き込む。閲覧時はシステムが自動でタグごとに統合・成形を行う。入力が気軽な点が優秀
- anytype：各メモがあらかじめ作っておいた型を一つ持つ。例えば「HCI論文」型をあてるとメモには自動的に「著者」「出版年」「評価」といった Relation（属性） の入力欄（スキーマ）が生成される。検索用インデックスを超えてデータ構造そのものをあらわす点がタグとの違い。普通のアプリではテーブル設計とSQLクエリは開発者が事前に行っておくが、anytypeではユーザーがこれらを自由に行えるようになっていると理解してもいいかもしれない

## 閲覧時と編集時で明示的な切り替えが必要か

keepはしていない。切替の身体的心理的負荷を考えて、できれば切り替えはしたくない。mdの場合、カーソルのある行だけプレーンテキスト表示されるインラインプレビューが主流。あるいは、画面を分割してもいい。閲覧画面の方はmdプレビューだけでなく、グラフィカルな見せ方でもOK。その場合、anytypeの型定義はめちゃくちゃ効いてくるな（どのメモでどの見せ方が可能かを容易に判断できる）。さらに拡張するなら、型ごとに拡張された独自のmdタグをつくってもいいかも。1100-1200 task としたら、勝手にグラフィカルにしてくれるとか。タグでもできるが、ひとつのファイルにはひとつの型だけ、タグは別で複数持てる、の方が散らばりにくさと検索効率を両立できるか。


## メモ同士の関係性をどう表現するか

双方向リンク、単方向リンク、ツリー、タグ（これはほかの構造と両立可能）などが考えらえれる。暫定解：物理的保存は階層とし、mdファイル内に以下のような情報を持たせる

``` text
id: 2026-02-10-task1
title: 実験データの分析
parent_folder: /projects/HCI-research/tasks  <-- 【階層】
tags: [urgent, analysis, python]             <-- 【タグ】
links: [doc-001, project-alpha]              <-- 【リンク】
```

## 必要としている機能の整理

現時点で、必要な機能は大きく以下の4つに大別できる

1. 単発で完了し所要時間や何をすべきかが明確なタスク（買い物に行く、デスク上を片付ける、など）とそれをいつ行うか（年月日と開始時刻と終了時刻）を管理する機能

2. 現在の所持品、購入を検討しているもの、各種の資産推移や運用状況、収支の管理、キャッシュフロー予測といった、私が物理的に所有するあれこれを管理する機能

3. よく使うコマンド集、3DPのスライス設定集、ポイント期限、サーベイした論文などといった、情報として私が所有するあれこれを管理する機能

4. 進行中・保留中のプロジェクトそれぞれについて、多種のサブ情報（概要説明、必要な材料、目的、機能要件、参考にすべき3の情報へのリンク、など）を管理する機能

## タスクとプロジェクトの優先度自動決定の仕組み

取り組みたいことが多すぎて、取捨選択のためのコストが無視できないため、LLMによって自動で優先順位を決定することを検討中。以下のような方法が考えられる。
- あらかじめ設定した指標（緊急度、重要度、所要時間、心理的ハードル、社会的インパクト）によってLLMが優先度を決定
- ユーザーがより長時間、閲覧や編集を行ったものの優先度を高くする、ユーザーが一定時間触れていないタスクの優先度を下げる（あるいはアーカイブしたり、削除可否をユーザーに問う通知を出したり）
- 他のタスクに、より依存されているタスク（PCケースの3DPが終わらないと自作PCの組み立てに着手できない、など）の優先度を高くする
- スケジュールを参照し、ユーザーの使える時間や疲労状況を推測、それをもとに、適切な時間帯に適切なタスクを割り当てる
